# 2026-09-14 缺陷修复四连：删除绕过 / 并发丢更新 / 补救单元死锁 / 重复细化覆盖

来源：外部代码审查（本地克隆逐行 review）+ 复现。四个缺陷全部属实，本轮修复并全量验证。

## P1-A 删除密码绕过
- 现象：`/state/delete` 无密码 403，但同一份资料经 `/state/del` 无密码即可删除（绕过）；同类第三条路：`/state/put` 写 null 墓碑。
- 根因：三处删除写入口，仅 `/state/delete` 校验 DELETE_PASSWORD。
- 修复（study_assistant.py）：
  - `/state/del` 与 `/state/delete` 合并进同一分支（同一密码校验；未配置 503 / 错密码 403）。
  - `/state/put` 拒绝 null 值（400），删除一律走带密码端点。
  - 前端（path_app.js）：`clearSave()`（「重新开始」原会静默删除当前资料）移除，重新开始改为不删资料（确认文案同步）；遗留 untitled 清理不再删除旧键。
- 验证：密码矩阵 12 项全绿（403/400/503/200 + 键存活）；生产探针 del/delete 无密码 = 403、put null = 400。

## P1-B 并发保存丢数据
- 现象：节点材料保存成功，但并发更新的学习计划被覆盖丢失。
- 根因：`_state_merge_put` 的读取与写入各自加锁，「读-改-写」非原子。
- 修复：`STATE_LOCK` 改为 RLock；读-改-写收进同一临界区。
- 验证：24 线程并发对照——旧版丢 23 个更新（FAIL）；新版 0 丢失（PASS）。

## P2-③ 补救单元被锁（死锁语义）
- 现象：自测不及格后生成的细化单元，依赖原单元「先通过」才能打开，补救材料永远打不开。
- 修复：后端 `/path/refine` 新节点打 `refine: true` 标记；前端 `isUnlocked` 对细化单元改为「原单元可达即可学」（依赖已完成或依赖本身已解锁，含环保护）。
- 验证（浏览器实测）：细化卡 n34/n35/n36 显示「可学习」且点击可展开出正文；普通锁定节点（n2 等）保持锁定、点击不展开。截图：zz_fix_unlock.png。

## P2-④ 重复细化覆盖
- 现象：测验页发送「打开页面时缓存的旧计划」，后端据此重新编号并整份覆盖保存，第二次细化抹掉第一次新增单元。
- 修复：`/path/refine` 改以服务端已存储的最新 plan 为基准（客户端 plan 仅兜底）——服务端唯一数据源。
- 验证：两轮细化（第二轮故意发旧计划）——旧版 33→35→34（第一批被覆盖）；新版 33→35→36（两批全保留 + 标记正确）。
