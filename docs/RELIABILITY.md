# 持久化、后台任务与恢复

## 当前模块结构

后端仍使用 Python 标准库 HTTP 服务。`study-assistant/application.py` 是组合根：它创建账号、SQLite、资料仓库、模型客户端、业务服务和路由，并将依赖传给各对象。HTTP 控制器负责请求适配。学习、测验、辅导和飞轮服务负责业务流程。`quiz_harness.py` 定义评分协议。后台任务调用应用操作分派，不创建 HTTP handler。

Python 文件由 `study-assistant/architecture.json` 声明为 domain、infrastructure、services、http、composition 或 tools。架构门禁检查每个文件的归属及导入方向。资料解析和渲染检查继续在单独 worker 进程中运行，并沿用各自的隔离边界。

浏览器仍使用原生 JavaScript，不引入前端框架。首页、学习路径、测验地图和测验窗口由 manifest 声明工厂依赖，构建为独立脚本。共享身份、保存、任务、任务详情、资料和 UI Kit 通过清单声明依赖并按顺序加载。页面模块通过入口连接具名 hooks，不读取其他模块的内部状态。目录职责、调用流和 UI Kit 接口分别见 [系统架构](ARCHITECTURE.md) 与 [前端 UI Kit](UIKIT.md)。

下文保留持久化、队列、Schema、配置、备份和回滚约束。模块拆分没有改变这些数据恢复边界。

## 决策及影响

| 原问题 | 当前实现 | 边界 |
| --- | --- | --- |
| 多个 JSON 文件逐项写，半批失败不可回滚；进程锁不能覆盖多进程 | SQLite 文档表，WAL、FULL、BEGIN IMMEDIATE，批量操作一个事务 | 一台主机一个后端写进程；线程并发执行网络调用 |
| 浏览器刷新丢失长请求的连接与结果 | 持久化 jobs 表，用户回执去重，后台执行、查询、重试 | 未完成且无 effect 的单元任务按剩余预算恢复；其他运行任务重启后标为 interrupted；不承诺上游推理恰好一次 |
| 生成与用户进度更新相互覆盖 | 短事务合并，服务端保护生成内容、题集和成绩；删除墓碑 | 普通用户字段仍按最后一次成功写入处理；API 可传 expected 修订前置条件，尚非协同编辑 |
| 追加细化、生成综合测验在崩溃后重复追加 | 新资料及任务 effect 在同一事务提交，重启从 effect 完成回执 | 其他操作依靠已保存节点/轮次/尝试标识恢复 |
| 保存失败只输出控制台，关页后难恢复 | 串行写队列、用户隔离的本机待保存副本、可见重试；恢复前阻止旧页面覆盖副本 | 浏览器清理存储会删除未同步副本；账号只读查看不加载他人副本 |
| 同主题路径被复用为同一资料 | 新建资料使用随机后缀，标题与 URL 存储标识分开 | 旧 URL、旧资料 ID 保持可读取 |
| 多份硬编码 API 地址需要重建页面 | `/learn/config.js` 提供运行配置，全部页面使用同一身份客户端 | 自定义反向代理地址还需配置部署侧 CORS/路由 |
| 页面对后台等待、失败、恢复提示不一致 | 公共 UI 样式与状态组件、首页近期任务、评分弹窗恢复与手机布局 | 学习路径与测验共用交互组件，独立知识地图已移除 |

## 存储及 Schema

`STATE_DIR/state.sqlite3` 是迁移后的唯一学习数据源。`documents(key,value,updated_ms,revision)` 保留 JSON 文档语义及删除墓碑。`metadata` 保存导入文件及 SHA-256；`jobs` 保存用户、回执、操作、输入、状态、结果、错误和已提交副作用。`job_attempts` 保存当前重试周期的执行次数、开始时间和下一次执行时间。`job_details` 保存有界任务事件，包括生成阶段和模型请求/回复。`job_attempts` 与 `job_details` 都是可选的任务元数据扩展；数据库版本保持 `PRAGMA user_version=1`，旧代码可保留并忽略这些表。旧文档的值、修订号和时间戳不变。未知版本拒绝启动。

首次启动在一个事务内导入旧 `*.json` 文档信封 `{key,v,ts}`，坏文件使整个导入失败，原文件保持不变。导入成功后不会再回退读取这些旧 JSON。**数据库已有新写入时，不能用旧 JSON 或旧备份覆盖来回滚程序。**

`state_schema.py` 在浏览器数据合并前检查：路径阶段、节点结构和 ID、进度状态、讨论消息、知识标记及测验基本结构。兼容旧文档缺省字段，保留未知字段；已存内容不做破坏性批量清洗。所有权、删除和成绩权限由业务层独立检查。SQLite 存储版本与文档 Schema 版本相互独立。

学习资料保存时，服务端在事务内读取最新文档。输入缺少的根级字段继续保留，旧页面省略扩展字段不会删除它们。输入明确提供的值按原有规则处理；可编辑扩展字段可更新为 `null`。题集、成绩、补图和路径仍受服务端保护。合并后的整份文档仍受体积限制，删除墓碑不受此规则影响。

## 锁与任务

后端启动持有 `STATE_DIR/.writer.lock`，同目录第二个写进程拒绝启动。账户仍在 `STATE_DIR-accounts/accounts.json`，采用写临时文件、fsync、replace 和目录 fsync；失败时恢复内存副本。SQLite 负责学习状态事务。模型、检索和其他网络调用不持有 SQLite 写事务。单飞等待不会因经过固定时间就替换仍存活的执行线程。

`POST /jobs` 使用 `operation/body/request_id`；同用户同回执与同一 SHA-256 输入重用已有任务，不同输入返回 409。`GET /jobs` 优先返回运行中的任务，再按时间返回共最多 100 个摘要；`GET /jobs/<id>` 返回状态和结果；`GET /jobs/<id>/details` 返回用户有权查看的任务详情；`POST /jobs/<id>/retry` 继续失败或中断任务。详情接口复用任务归属检查。普通用户不能读取其他用户的详情。旧任务没有详情记录时返回 `available: false`，不尝试补造历史记录。开始执行前检查账号是否启用；停用账号不取消已经开始的任务，最终落盘仍遵守资料存在性和删除墓碑边界。

默认 2 个后台线程、全局 64 个排队/运行任务、单用户最多 8 个；超限返回 429。已完成/失败/取消回执在启动时清理 30 天前记录，中断任务保留待处理。浏览器断线只重新查询，不在轮询中重建任务；关闭页面后后台继续。直接旧 `/path/*` API 为兼容保留。服务器返回任务失败信息，原输入与成功阶段保持可恢复。

所有后台任务的每次执行预算为 300 秒。节点生成 `/path/node` 与自动动画 `/path/node/scene` 各最多执行两次，第一次失败后最多自动重试一次，间隔 5 秒。自动重试只处理已识别的网络传输异常、执行超时，以及上游 HTTP 408、429、500、502、503、504。权限、资料删除、409 冲突、内容校验和程序错误保持失败终态。超时回执说明预算、失败阶段、尝试次数和是否等待重试。其他操作不自动重试。每个任务详情按用户和任务保存有界事件。事件可记录阶段、模型实际请求消息和最终回复、HTTP 类别及程序位置；不记录模型内部推理。保存前移除凭据。详情长度超限时标记截断。服务重启和用户手动重试分别记为事件。已存在的旧任务没有历史详情。

`/path/node/scene` 的两次上限是后台队列的外层执行次数。每次执行仍有独立的 300 秒预算。一次执行内部，Manim 代码格式、源码、渲染和媒体问题最多修复一次；独立教学复核问题（包括复核回复格式无效）也最多修复一次。技术类修复后再次出现技术类问题，或教学复核类修复后再次出现复核问题，都立即停止。只有这两类问题先后各出现一次时，才可能有第三次代码调用。内层最多三次代码调用和两次独立复核，不改变队列的两次外层上限。模型传输异常按原样交给后台队列，并由既有重试规则处理。此规则只适用于 Manim 代码生成与教学复核，不改变旧 `learn-scene` 的首次生成加一次补生成规则。

节点材料分两步生成。前端先以 `defer_visual: true` 提交 `/path/node`。服务端验证并保存正文和题目，不等待动画。页面显示材料后，再单独提交 `/path/node/scene` 请求自动动画。动画失败只更新 `manim_review`，保留正文和题目；没有合适动画时标记 `not_needed`。刷新页面只读取并继续观察已有任务回执，不重新提交生成请求。用户单独重试动画时只创建动画任务，不换题或改学习进度。批量生成在页面只显示一条汇总，再提供任务错误和原始日志详情；暂停时等待当前单元及其自动重试结束，然后停止启动下一单元。

节点的正文渲染复核若拒绝候选，服务端丢弃该正文候选，并在当前节点生成循环内重新生成正文和题目。它不会只修复题目后复用被拒绝的正文。该循环最多三次，仍沿用 `/path/node` 每次执行的 300 秒预算和后台队列最多两次的外层执行上限。三次后仍未通过时，任务失败，不保存候选，不改变已有正文、题集或学习进度。渲染复核不可用、取消和超时不会转成新的内容修复循环；它们按现有错误和重试规则处理。

有后台执行预算的模型复核保留 HTTP、超时和 URL 传输异常，由队列判断是否重试。回复格式错误、内容不合格和本地渲染不可用仍失败关闭。没有后台执行预算的复核调用继续返回原有不可用结果。

`job_execution.py` 给同一工作线程的业务、网络和渲染传递剩余预算。`model_transport.py` 的短命子进程只执行非流式模型 HTTP 和搜索 HTTP，不访问 SQLite。输入和密钥经 stdin 传入。响应最多 16 MiB。父进程按绝对传输时限终止并回收网络子进程后才返回失败，避免持续少量响应使 socket 超时失效。流式辅导接口仍使用既有传输。

节点正文、题集和 job effect 在同一事务提交。提交后的 effect 恢复为成功，不再次生成或签发题目。普通动画失败仍保存已校验正文；整项执行截止必须向上传播，并在最终写入前检查。界面显示本次开始时间和任务阶段，历史 created_ms 不再代表本次耗时。磁盘持续不可写时，服务不能保证持久化任务终态；工作线程保留结果并等待存储恢复。

## 配置

`app_config.Settings` 启动验证端口、HTTP(S) 上游地址、模型、超时、请求体和队列上限。秘密值只使用服务器既有环境配置，公共 config.js 不包含密钥。

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| `UPSTREAM_TIMEOUT` | 180 秒 | 上游单次请求超时 |
| `MAX_OUTPUT_TOKENS` | 393216 | 保留原模型输出预算 |
| `MAX_REQUEST_BYTES` | 16777216 | 读取请求体前的硬上限 |
| `BODY_TIMEOUT` | 30 秒 | 接收请求体超时 |
| `JOB_WORKERS` | 2 | 后台工作线程 |
| `JOB_QUEUE_LIMIT` | 64 | 排队和执行中任务总量 |
| 静态服务 `--api-port` | 8101 | 当前页面主机上的后端端口 |
| 静态服务 `--api-base` / `API_PUBLIC_BASE` | 空 | 完整后端地址或同源代理前缀 |

认证后还会检查任务输入 2 MB 上限。流式 HTTPS 使用系统证书校验。错误请求返回明确的 400/408/413；数据库故障返回 503。

## 备份与回滚

1. 等待后台任务完成，停止后端，保留运行配置、代码版本及静态资源。
2. 执行 `python3 backup_state.py <STATE_DIR> <新的备份目录>`。备份目录须位于状态和账户目录之外。脚本持有同一进程锁，以 SQLite backup API 包含已提交 WAL。脚本同时备份账户目录、现有 `STATE_DIR/manim-assets` 和 `STATE_DIR/manim-runtime.json`。动画备份包含视频、关键帧、清单、绑定记录和私有源码。没有动画目录的旧环境仍可备份。文件按块复制，不设置整个资产库的大小上限。符号链接、硬链接和特殊文件使备份失败。只有全部复制成功后才写入 `manifest.json`；没有该清单的目录不是成功备份。不要只复制活动数据库主文件。
3. 恢复时保持服务停止。将配套 `state.sqlite3` 恢复到 `STATE_DIR`，将备份的 `accounts` 恢复到 `STATE_DIR-accounts`。将同一备份中的 `manim-assets` 和 `manim-runtime.json` 恢复到 `STATE_DIR`。维持目录 700、文件 600。动画引用和文件必须来自同一快照。核对运行镜像仍可用，再启动服务。验证 quick_check、登录、资料数量、业务读取和已保存动画播放。已有新写入时，不得用旧备份覆盖当前数据库或动画文件。
4. 升级首次迁移核对全部旧文档键、值、时间戳及旧文件哈希。升级后有写入则优先修复当前版本；回退旧 JSON 版本需要停写并从权威数据库转换当前文档和墓碑，经核对后再切换，不能直接启动陈旧文件版。

代码回退必须保留当前权威数据库和新增任务元数据。不得用升级前备份覆盖新数据来回退。旧代码不提供新增的自动重试保证；发布失败时应核对实际任务状态，再修复当前版本。

隔离回归使用 `192.168.33.146:8112/learn/` 与后端 `:8111`，独立 STATE_DIR。正式固定入口保持 `:8100/learn/`，部署不引入测试资料。

## 验证

`sh scripts/check-local.sh` 覆盖身份边界、服务端评分保护、事务回滚、旧文件导入、跨进程更新、WAL 备份、回执去重、容量限制、重启恢复、追加副作用原子性、后台调用不阻塞保存，以及前端保存重试和任务重连。浏览器再验证登录管理、刷新续接、同主题独立创建、失败提示、手机首页、管理员只读和真实模型链路。发布结果以单独验收记录为准。
