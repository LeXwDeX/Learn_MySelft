# 学习文档标题契约

同一篇资料无论从首页、资料库、近期任务进入，或在详情、浏览器页签、测验窗口查看，都使用该文档顶层 `title`。显示层不得用 `topic`、`spec.topic`、`plan.title`、文件名、路径、slug 或任务请求正文另起名称。

## 数据结构

| 字段 | 含义与归属 | 可否作为文章标题 |
| --- | --- | --- |
| 文档 `title` | 服务端维护的正式名称；学习地图和综合测验均使用 | 唯一来源 |
| 文档 `topic` | 用户首次输入或最初上传主题，保留用于对话上下文 | 否 |
| `spec.topic` | 模型整理的学习领域，与 goal 等构成需求单 | 否 |
| `plan.title` | 旧版本遗留字段；只用于一次性旧数据迁移，正文历史保留 | 否，新路径不再生成 |
| `plan.nodes[].title` | 各知识单元自身的名称 | 仅该单元标题 |
| 原 `task_titles` 表 | 旧模型短标题，迁移输入，迁移后不再读写作为运行来源 | 否 |
| 响应 `task_title` | 兼容旧页面的别名，与响应 `title` 完全相同，不独立存储 | 新代码读取 `title` |
| key / slug | 稳定身份与链接；不随标题变化 | 否 |

## 生成和写入

1. 需求确认模型在原有同一次回答中输出 `TITLE:`：具体学习目标的纯文本短标题，最多10个Unicode字符。不复制用户请求原句、文件名或路径；范围变化时可更新。
2. `/path/intake` 把规范化名称写到现有学习文档的 `title`。后台任务仅记录回执，不再维护另一份标题表。资料已删除时不能因标题写入而复活。
3. 路径生成只生成摘要、节点及依赖。后续单元生成、细化、作答和评分均不另起文章名。
4. 新综合测验的 `title` 由源学习文档 `title` 加“综合测验”组成，在生成题目时写入测验文档。模型不重复生成文章名。测验有自己的稳定文档身份，列表与详情都显示测验文档 `title`；“来自”引用源文档 `title`。
5. 浏览器 `/state/put` 快照无权改写既有 `title`，即使来自旧页面或旧本机草稿。缺少名称的初始化文档统一使用“学习资料”；不会把原始请求假装成正式名称。正常保存、草稿恢复忽略服务端拥有的标题差异。

## 旧数据迁移

`canonical_document_titles_v1` 是一次性事务迁移。学习地图已有非空顶层 `title` 则保留；否则按同用户同key旧任务短标题、旧路径标题、Spec主题、可用简短主题补齐，无法判断则用“学习资料”。请求句或上传路径不作为回退名称。

综合测验保留已有有效正式标题；缺失或仍是请求句的标题从源文档正式名称派生。迁移只修改顶层 `title`、对应记录revision及迁移标记，保留原更新时间、所有其他字段、已删除标记、账号及配置。第二次启动不再迁移。原表和旧路径标题保留为历史，不再参与显示。

发布前对旧库备份，在副本上预演迁移，再验证正式变更只涉及允许字段。无需调用模型批量重命名。

## 引用与验收

前端 `LearnTitles.document(document)` 只读 `title`，异常或空值统一显示“学习资料”。`LearnTitles.quiz` 只分别读取测验和源文档的 `title`。后端近期任务从任务key关联的文档读取同一字段。

验收同时检查首页列表、路径资料库、测验选择列表、路径详情主标题和页签、测验详情及测验窗口，并在刷新后重复比较。覆盖模型生成、历史迁移、迟到快照、删除中生成、用户隔离、旧任务回执和本机恢复。
