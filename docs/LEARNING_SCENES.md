# 学习正文交互场景

新的教学动画使用真正的 3b1b ManimGL 1.7.2。原生模式的动画任务返回 Python 场景代码；匹配的 helper 模板由服务端按参数生成代码。代码只在无网络、限资源的容器中运行。浏览器播放实际渲染的视频，并按步骤暂停。旧的 `learn-scene` 浏览器图形协议继续用于历史资料显示。

## Manim 教学链路

1. 正文生成服务判断图形是否能帮助理解。补图操作与辅导的动画请求使用同一个 `ManimService`。辅导只按本次问题判断动画请求，不把历史问题或学习正文当成本次请求。
2. 动画先经过一次规划模型调用。规划读取服务端当前正文、本次问题、级别和学习目标。它返回 `needed`、`reason`、`objective`、`recipe` 和 `parameters`。正文内容只作为资料，不执行其中的指令。规划无效时停止，不重试规划，也不改用 `native`。没有动画价值时，自动任务不渲染；明确要求动画时不能静默省略。
3. 规划只选择一个教学关系。`recipe` 表示服务端支持的场景模板类型。已验证的 helper 模板只有 `shear_basis` 和 `swap_components`。这两个有限模式不能代表所有题材都已通过验证。题材与参数匹配时，服务端按参数生成 helper 调用和对应的两步教案，不调用代码生成模型。选择依据是数学关系，不是关键词。题材或参数不匹配时，规划须返回 `native` 和空参数，由原生 Manim 代码讲解唯一目标。服务端不把已验证 helper recipe 的越界参数自动改成 `native`；这种规划无效并失败关闭。helper 初稿计为第 1 个候选；只有合法 helper 候选之后发生媒体或教学失败时，才可改用原生代码，并占用对应的技术或教学修复机会。
4. 原生代码生成只围绕规划选定的 `objective`。正文和问题可提供事实，但不引入第二个教学目标。修复时保持这个目标，并先删除无关对象和步骤，再修正代码或布局。`teaching_plan` 有 `objective`、`visual_reason`、`observe` 和 1 至 8 个 `steps`；前三项上限分别为 120、200、160 个字符，每步只含 `change` 和 `why`，各不超过 160 个字符。计划步骤须与代码步骤一致。服务端在渲染前校验字段和长度，再核对计划步数与实际视频步骤。计划保存在私有资产中，不加入公开围栏。每步代码以 `self.next_step(caption)` 结束。它记录实际帧边界，并保持结果至少 0.7 秒。
5. 第一容器使用真正的 ManimGL 渲染。产物通过有界标准输出收集。容器及全部后代清理后，第二个新容器检查视频和步骤数据。
6. 第二容器完整解码视频，检查尺寸、帧率、帧数与步骤边界。它还检查每步实际发生画面变化，且结果保持静止。输出为 H.264、yuv420p、1280×720、30 fps 的 MP4 与每步结果 PNG。
7. 第二容器从实际视频为每步生成三张 240×135 手机复核 PNG：步骤开始、变化中和结果。复核图仅用于内部检查，不进入公开资产。渲染器检查数量、大小、编码、PNG 结构与尺寸。缺失或无效时失败关闭，不回退原分辨率截图。独立教学复核继续检查真实视频、来源正文、本次问题和 `teaching_plan`。使用 helper 不会跳过复核，也不会自动通过复核。三张抽样图不能证明未采样帧中的全部动作正确；发现过程有歧义时应拒绝。技术问题与独立教学复核问题分别最多修复一次；任一类修复后再次出现同类错误即停止。只有两类问题先后出现时才可能生成第三稿；最多三次代码调用、两次独立复核。渲染或检查不可用时，不发布动画，不用旧浏览器场景替代。

Manim 渲染失败时，worker只在本地从最多 64 KiB 的 `stderr` 尾部提取受限诊断。诊断对象不包含原始 `stderr`、容器路径或源码片段。诊断只接受 `TypeError`、`AttributeError`、`NameError`、`ValueError`，可带生成源码中有效的 1 起始行号。`TypeError` 可带 `keyword`，`AttributeError` 可带 `attribute`，`NameError` 可带 `name`；`ValueError` 不带标识符。标识符必须是最多 64 个 ASCII 字母、数字或下划线组成的名称，且首字符必须是字母或下划线。worker和 API renderer 都会拒绝额外字段、错误类型或越界值。只有通过两层校验的类别、行号和标识符会进入服务端私有修复提示；它们不会写入公开动画资产或 `manim_review`。修复模型请求仍遵守现有任务归属和详情展开规则。旧 worker 只返回通用 `scene_render_failed` 时仍按通用失败处理；无法识别的异常也不附加诊断。

动画返修只携带与上一稿代码配对且通过字段校验的教学计划；计划步数与真实渲染 `manifest` 不符时，提示会给出计划步数/manifest 步数（X/Y），未通过校验的原始计划不会回传。

8. 服务端重新检查账号、资料、节点与来源正文。资产绑定由服务端发布。资料或节点删除后，媒体请求被拒绝。普通用户只能访问自己的动画；管理员查看其他用户资产时只读。
9. 页面初始显示封面，不自动播放。点击“自动播放”会立即从当前步骤开始，按顺序播放到最后一步。它不是开关，也不使用 `aria-pressed`。普通“播放”默认按步骤顺序播放。“重播本步”只播放当前步骤。播放结束后，画面停在末步结果。播放器也支持上一步、下一步和本步定位。
10. 每步视频以原始速度的 90% 播放。动态内容到达本步保持区间后，播放器暂停视频，并显示该步的真实结果图。结果图固定显示 250 毫秒。此间隔不随视频速度变化，也不叠加视频原有的尾部静止帧时间。随后播放器定位到下一步起始帧。定位成功后，播放器切换到新步骤并继续播放。定位期间保留上一结果图。画面不淡出、不淡入，也不变成空白。
11. 暂停、切换步骤、拖动进度、页面隐藏、播放错误、卸载或重新加载时，播放器会取消尚未执行的间隔和旧定位回调。画面透明度保持为 1。减少动态效果偏好不会改变步骤间的显示或 250 毫秒间隔。Agent 灯箱复用同一播放器实例。
规划新增一次模型调用，会增加动画生成延迟。规划、代码生成、渲染和复核共用原有 600 秒后台预算。规划只调用一次；格式或内容无效时停止，不另起规划修复循环。原生路径在一次规划后最多调用代码模型 3 次。helper 路径由服务端生成第 1 个候选，不调用代码模型；如果失败，改用原生代码会占用对应的已有修复机会。每次后台执行最多处理 3 个候选、最多独立复核 2 次。技术修复和教学修复各最多一次；同类问题在对应修复后再次出现时立即停止。规划、代码生成和代码修复请求均将 `reasoning_effort` 设为 `none`。规划最多输出 2048 token；代码生成和修复的输出上限为管理员 `max_output_tokens` 与 16384 中的较小值。独立教学复核首问沿用原配置的低推理档位（`low`）和 8192 token；仅当首问返回纯空白时，对同一候选补问一次，改用 `reasoning_effort=none` 和同一上限，并在用户内容中重申开始帧建立规则和精确 JSON 字段。补问复用同一渲染，不增加候选或复核轮次。其他业务调用沿用原配置。自动执行仍最多两次；上游传输异常仍按原有后台重试规则处理。这些限制不保证上游及时返回，也不保证截断输出可以恢复。

Manim renderer 保留一个渲染槽位，不增加并发渲染。槽位被占用时，新任务按短间隔等待，并在等待中检查取消和任务截止时间。等待时间计入同一 600 秒动画预算。`ManimService.generate` 使用 600 秒内层预算；如果任务已有更早的截止时间，则使用更早的时间，不延长或重置它。AI 辅导动画也使用这项预算。取消或超时发生在获得槽位前时，不启动容器；获得槽位后，无论成功、失败、取消或超时，都会释放槽位。此调整不改变合法 helper 的选择和参数要求，也不改变媒体检查或独立教学复核。

`learn-manim` 围栏仅保存服务器资产引用：`version`、`asset_id`、`title`、`summary`。模型不能自行发布资产链接。实际代码保存在私有资产目录，不由媒体接口提供。MP4 接口支持经过授权的单段 Range 请求，方便 Safari 定位。

单个动画最多 8 步、90 秒。运行容器限制为 2 GiB、2 CPU、512 个进程。根文件系统只读；网络关闭；不挂载账号、状态库、主机目录或 Docker socket。AST 检查只用于发现错误，不是代码沙箱。两个容器才是代码执行和媒体解码的隔离边界。

取消或保存失败会清理本次未使用的资产。服务启动时，回收超过 24 小时的未发布资产和无元数据残留。已发布资产和元数据状态不明的资产保留。当前文档没有引用不能证明历史聊天或浏览器没有引用，因此不据此自动删除已发布资产。

运行环境使用 `deploy/manim-runtime/Dockerfile` 与带哈希的 `requirements.lock`。发布包包含这两份文件。以发布包的 backend 目录为构建上下文：

```sh
docker build -f manim-runtime/Dockerfile -t zixueshe-manimgl:1.7.2 .
```

worker 输出合同改变后，必须同步重建镜像并更新固定哈希。旧镜像缺少手机复核图，不能视为检查通过。

将该镜像的固定 `sha256:` image ID 写入本环境 `STATE_DIR/manim-runtime.json` 的 `image` 字段。不要写可变 tag。测试与正式环境各有自己的配置和资产目录。镜像构建需要网络；运行时关闭网络。缺少 Docker、配置或指定镜像时失败关闭。ManimGL 使用 MIT 许可证；源与版本保留在独立依赖中，不复制进第一方业务模块。

浏览器播放服务端生成的 MP4，不重新计算 Python/OpenGL 场景。它不等于完成 Manim 的浏览器原生移植。

## 数学教学方法

`prompts.MATH_VISUAL_TEACHING` 是正文、辅导、动画生成和独立视觉复核共用的方法。它不包含 JSON 输出合同。独立换题、测验地图、验题和判分提示词不加载这份动画方法。

先按学习目标选择对象。图形有助于理解时才生成动画。服务端从本资料的 `spec.level` 和 `spec.goal` 读取级别与目标，并作为待审数据送入动画生成和复核。辅导接收同一资料的级别与目标。没有级别时不猜年龄，也不因出现本科术语就使用三维。

| 学习阶段 | 讲解起点 |
| --- | --- |
| 小学 | 具体数量、分组、分数份额和直观形状。 |
| 初中 | 连接图形与代数符号，显示变量、等价变形和几何依据。 |
| 高中 | 连接函数、参数与坐标，说明证明前提。 |
| 本科基础 | 逐步引入抽象结构、极限与多变量关系，保留定义和假设。 |

| 内容 | 图形讲解方法 | 必须说明的边界 |
| --- | --- | --- |
| 初等代数 | 显示方程两边同做一种运算。三元方程依次消元、减少未知量、回代。 | 定义域、不能除以零及等价变形的前提。 |
| 二维几何 | 突出已知条件、辅助线、角度和比例。 | 平行、垂直、相似等结论须有依据，视觉相等不等于证明。 |
| 三维几何 | 先看二维关系，再展示必要的视角、截面和投影。 | 区分真实长度与投影长度。转动视角不改变对象。 |
| 线性代数 | 用基向量与坐标解释组合，显示变换、独立方向、秩和投影。 | 区分向量与坐标表示。二维示意不代表高维实际形状。 |
| 单变量微积分 | 割线逐渐逼近切线，分割与黎曼和逐步变化。 | 区分有符号积分与几何面积。有限采样不是极限证明。 |
| 多变量微积分 | 联系等值线、梯度方向、局部曲面和切平面。 | 说明变量范围及保持不变的条件。有限网格不能代替论证。 |
| 概率统计 | 显示样本、频数、密度或区间面积。 | 密度高度不是单点概率。区分样本与总体，说明模型假设。 |
| 微分方程 | 给出初始条件，再显示方向变化和解轨迹。 | 区分方向场、解曲线与数值近似，说明自变量范围。 |
| 离散数学、图论、递归和抽象代数 | 用节点、边、状态或具体运算显示规则。 | 说明基例、终止条件或公理。具体例子不替代一般结论。 |

每次新生成只选最适合动画的一条关系，不必覆盖本单元全部目标。数学结论须有一般依据，不能只依赖程序或代码示例。

提示词含有可选的 `TeachingScene.shear_basis(k=1)` 参考。它只演示矩阵 `A=[[1,k],[0,1]]` 将 `e2=(0,1)` 变为 `(k,1)`，并保持原点不动。只有正文确实讲这一剪切关系时才使用；其他课程不能套用这个例子。`k` 必须是有限的 `int` 或 `float`，不能是 `bool`；范围是 `0.5` 到 `1.5`，最多三位小数。方法只能在尚无对象、步骤和动画的新场景中调用一次；调用前后不能添加对象、调用 `play` 或 `next_step`。方法内部固定记录两步，因此教学计划也必须恰好两步：第一步先显示固定原点 `O`、位于 `(0,1)` 的蓝色终点圆点和短标签，再用原生 `GrowArrow` 从 `O` 画出 `e2`。首帧不显示完整箭头。第二步隐藏活动标签并显示固定的粗灰色水平线；终点圆点沿线连续移动，箭头以同一原点变换，灰色原态保持不动。原点不变，`x` 坐标改变，`y` 仍为 1。动画结束后显示 `Ae2` 和目标坐标。画面按每个数学单位 3 个场景单位缩放；坐标和字幕由方法按 `k` 计算。这个参考不表示所有参数或自动生成链路均已通过媒体检查或独立教学复核，也不表示它演示了面积、`e1` 或网格。

提示词还含有可选的 `TeachingScene.swap_components(values=(3,-1,4))` 参考。它只用于正文确实讲三分量向量前两项交换的内容。`values` 必须是恰好三个 `int`，每个值在 -9 到 9 之间，且前两个值不同；`bool` 不算整数输入。方法只能在没有对象、步骤和动画的新场景中调用一次。调用前后不能添加对象、调用 `play` 或 `next_step`。方法固定记录两步：先显示三个有序槽位、分量编号、原向量和维度 3，再将前两个分量沿弧交换，第三个分量保持不动，并显示结果向量。字幕和向量由输入值生成。它不支持任意维度、任意排列或一般矩阵变换；其他内容使用常规 Manim 场景代码。

ManimGL 1.7.2 的线宽参数按对象区分：`Line(LEFT*2, RIGHT*2, stroke_width=6)` 使用 `stroke_width`；`Arrow(..., buff=0, thickness=5)` 的箭杆粗细使用 `thickness`。`Line` 不接受 `thickness`。服务端会在渲染前通过 AST 检查并拒绝这个错误参数，同时指出代码行和正确参数。已有的一次技术修复可按该反馈改正实际调用；这项参数检查不代表动画已经渲染或通过教学复核。

服务端还会在渲染前检查首帧声明。若第 1 步的 `change` 明确写“首帧显示/首帧即显示/首帧已有/开始帧已有”，代码必须在第一个 `self.play` 或 `self.wait` 前用 `self.add(...)` 放入这些对象；否则按源码/技术问题返回既有的一次技术修复，不进入渲染。若计划写“先建立/逐步显示”，则允许从空白开始。该检查只覆盖第 1 步 `change` 的显式措辞和 `self.add` 的位置，不校验对象身份、完整性或遮挡，也不检查后续步骤或 `why`；这些仍由独立复核和真实画面验收确认。

生成 JSON 仍使用六个根字段：`needed`、`reason`、`title`、`summary`、`teaching_plan` 和 `code`。教学计划只含 `objective`、`visual_reason`、`observe`、`steps` 四个字段。上述两个 helper 各自只用于对应的剪切或分量交换关系；它们不替代具体课程规划、媒体校验或独立教学复核。

每段教学先说明对象和前提，再请学习者预测变化。每步只改变一个主要关系。字幕说明动作及原因。结果停留后再进入下一步。计数须逐个显示或依次高亮，不能只放结论。移动对象组合时，数字和标签保持间距。更新强调时移除或变换旧强调。复杂问题拆成多个短片，每片保持最多 8 步、90 秒。

数学动画优先用 3 到 5 个因果步骤。只保留讲清目标所需的步骤。不要让所有主题套同一模板。目标复杂时拆成短片，不要塞满 8 步。每段要说明什么在变、什么不变、依据是什么。字幕要指向画面中可辨认的对象、位移或长度。为需要追踪的对象加清楚的短标签，并放在对应对象附近。有限采样只说明当前示例，不能代替一般论证。

剪切短片只选一条关系：基向量如何确定变换、点坐标怎样变化，或平行四边形面积为何不变。不要机械地把这些关系拼成一条动画。只有解释剪切前后面积不变时，才用变换前后对应的底长和垂直高说明依据。不要用有间隙的条带声称铺满区域，也不要只放“面积 = 1”代替理由。

纯标题和装饰不单占教学步骤。每步动作与原因须对应可见的知识关系。重复同一结论而没有新关系时合并步骤。仅有淡入淡出不能证明教学递进。合理循环可以回到原态；复核判断变化是否推进理解，不机械要求每张结果图不同。

画面显示对象、运动和短标签。完整推导、条件和复杂公式放在旁边正文，由现有 KaTeX 渲染。当前场景生成使用已有真实 ManimGL 图元与动画接口。中文短标签使用 `self.label()`，默认字号 96。主要方程、数值与关系优先使用 96–120 字号，并集中展示少量短行。名义字号不能证明实际可读；以真实 240×135 复核图及手机页面验收为准。长解释放在字幕和正文，避免用大块空白挤小主要关系。次要坐标轴和三维标签按教学需要设置。当前不使用 `Tex`，不加载外部文件，不为课程新增未经核验的 API 或另一个图形引擎。三维题可以先用二维截面和投影解释，不能虚构已经支持的三维操作。动画与正文都不得泄露尚未作答的测验答案。未生成或未通过检查的动画不能称为已经显示。

## 历史兼容：浏览器场景 v1

以下内容说明历史 `learn-scene` v1 协议，用于读取和显示已有资料。它不代表当前生成行为。新的学习资料自动动画、补图和 AI 辅导动画使用上方 Manim 链路。现有资料不会被批量改写。

## 使用范围

- 历史学习节点正文可能包含 `learn-scene` 场景。
- 当前 AI 辅导动画使用上方 Manim 链路，并输出服务端资产引用。
- 本协议只约束历史 v1 场景。测验题、参考答案、解析、重出题、测验地图、评分、建议问题和资料采集不使用 v1 场景。
- 旧版生成按空间、结构、数量比较、变化过程或推导评估图示价值。场景最多四个，默认不自动播放。线性变换和通用图解场景提供分步控制；割线和曲面截面场景提供参数滑块。`min` 等于 `max` 时滑块禁用。节点正文与辅导回答的旧字数限制不计入场景 JSON。
- 学习正文和 AI 历史保存原始 Markdown 与 JSON 围栏。既有 Markdown 导出保留原始源。滑块位置和暂停进度只存在于本次页面实例，不新增数据库字段，也不跨设备保存。
- 普通节点正文归一化仍最多 3000 个字符。包含场景围栏时，正文总上限为 50000 个字符，容纳四个完整场景及引导文字。超限内容仍会截断；渲染器对截断的场景显示不完整提示，不会补写源内容。发布时不批量重写旧资料。旧资料可以通过下文补图操作追加图示。

## 围栏格式

场景使用 `learn-scene` 围栏。围栏内是一个 JSON 对象。对象的字段由 `version` 和 `type` 决定。节点生成时，围栏文本放入既有材料 JSON 的 `study_notes` 字段，不取代外层材料结构。

v1 通用字段如下：

| 字段 | 要求 |
| --- | --- |
| `version` | 必须是数字 `1`。 |
| `type` | 必须是下文列出的类型之一。 |
| `title` | 去除首尾空白后非空，最多 80 个字符。 |
| `summary` | 去除首尾空白后非空，最多 500 个字符。 |
| JSON 源 | 每个围栏最多 12,000 个字符。 |

只允许各类型列出的字段。未知字段、未知类型或版本、语法错误、超长内容、非有限数和布尔值冒充数字都会被拒绝。`NaN` 与 `Infinity` 不是有效 JSON 数值。生成时每个字段只写一次；解析沿用 `JSON.parse` 的重复键后值覆盖规则。

## 场景类型

### `diagram`

`diagram` 用受限图元描述二维或三维图解。二维向量是它的一个用例。向量图只表示二维坐标中的分量关系，不代表真实的大模型高维嵌入。具体类比由 `summary` 和正文说明。

允许字段：`version`、`type`、`title`、`summary`、`dimension`、`elements`、`steps`。

- `dimension` 可省略，默认 `2`；也可为 `3`。三维图提供斜视和俯视。
- `elements` 必填，包含 1 到 40 个图元。每个图元的 `id` 唯一，符合 `[a-zA-Z][a-zA-Z0-9_-]{0,31}`。
- `kind` 只允许 `point`、`line`、`arrow`、`polyline`、`polygon`、`circle`、`label`。
- `points` 必填。每个点有 `dimension` 个坐标，各坐标是 `[-10, 10]` 内的有限数。`point`、`label`、`circle` 各有 1 个点；`line`、`arrow` 各有 2 个点；`polyline` 有 2 到 16 个点；`polygon` 有 3 到 16 个点。
- `circle` 必须有 `radius`，范围是 `(0, 10]`。其他图元不得有 `radius`。
- `color` 可省略，默认 `accent`；也可为 `secondary`、`muted`、`positive`、`warning`。`opacity` 可省略，默认 `1`；范围是 `[0, 1]`。`label` 可省略；给出时原文本最多 80 字符。图上显示标签，图下保留完整图例。手机上过长的图上标签会截短。
- `steps` 可省略，最多 8 步。每步只有 `caption` 和 `changes`。`caption` 原文本最多 300 字符，且去除首尾空白后非空。`changes` 有 0 到 40 项，每项只允许 `id`、`points`、`radius`、`opacity`。同一步不能重复修改同一 `id`。`id` 必须属于 `elements`。每项至少修改一个字段。新 `points` 的点数必须与该图元初始点数相同；坐标范围不变。只有圆可改 `radius`。

初始图元是第 0 步。后续步骤依次继承前一步的终态，再应用 `changes`。播放时对坐标、半径和透明度作插值。控件提供开始、暂停、继续、上一步、下一步、重播、慢速和本步进度滑杆。没有步骤时只显示静态图和三维视角控件。减少动态效果偏好下，手动换步仍会立即显示结果。

```learn-scene
{"version":1,"type":"diagram","title":"二维向量分量","summary":"在二维坐标中，v=(2,1) 由横向分量和纵向分量相加得到；此图仅用于说明分量，不表示大模型的真实高维嵌入。","elements":[{"id":"axis_x","kind":"line","color":"muted","points":[[-3,0],[3,0]]},{"id":"axis_y","kind":"line","color":"muted","points":[[0,-3],[0,3]]},{"id":"e1","kind":"label","color":"muted","points":[[3,0]],"label":"e₁"},{"id":"e2","kind":"label","color":"muted","points":[[0,3]],"label":"e₂"},{"id":"horizontal","kind":"arrow","color":"positive","points":[[0,0],[2,0]],"opacity":0},{"id":"vertical","kind":"arrow","color":"secondary","points":[[2,0],[2,1]],"opacity":0},{"id":"vector","kind":"arrow","points":[[0,0],[2,1]]},{"id":"length","kind":"label","points":[[1,1]],"label":"|v| = √5","opacity":0}],"steps":[{"caption":"先看横向分量 2e₁。","changes":[{"id":"horizontal","opacity":1}]},{"caption":"再从横向终点加上纵向分量 e₂。","changes":[{"id":"vertical","opacity":1}]},{"caption":"由勾股定理，长度是 √(2²+1²)=√5。","changes":[{"id":"length","opacity":1}]}]}
```

通用图解可表达向量、集合、函数采样、几何变形、信息流、系统状态与三维关系。图元标签在图中显示，图下保留完整标签。过长标签可在图中缩短；完整文本仍可从图例读取。三维圆位于其中心所在的 xy 平面；其他朝向的圆可用采样折线表示。

### `linear_transform`

允许字段：`version`、`type`、`title`、`summary`、`matrix`、`vector`。

`matrix` 必填。它是行顺序的 2×2 数组。四个值必须是 `[-4, 4]` 内的有限数。矩阵的列向量分别是 `Ae₁` 和 `Ae₂`，不能把行当成列。

`vector` 可省略，默认值是 `[1, 1]`。给出时必须是两个 `[-3, 3]` 内的有限数。图形展示 `Av = v₁·Ae₁ + v₂·Ae₂`。

```learn-scene
{"version":1,"type":"linear_transform","title":"列向量变换","summary":"A 的两列分别映射 e₁、e₂；v=(1,1) 映射到 Av=(3,3)。","matrix":[[2,1],[1,2]],"vector":[1,1]}
```

### `secant`

允许字段：`version`、`type`、`title`、`summary`、`coefficients`、`domain`、`baseX`、`gap`。

- `coefficients` 必填。数组长度为 1 到 5，按升幂排列。每个值在 `[-20, 20]` 内。例如 `[0,0,1]` 表示 `x²`。
- `domain` 必填。两个端点都在 `[-5, 5]` 内，且左端小于右端。
- `baseX` 必填，且在 `domain` 内。
- `gap` 必填，格式为 `{"min":数,"max":数,"value":数}`。必须满足 `0.01 ≤ min ≤ value ≤ max ≤ 3`，并且 `baseX + max ≤ domain` 的右端。
- 允许 `min` 与 `max` 相等。这时参数滑块禁用。

```learn-scene
{"version":1,"type":"secant","title":"割线趋近切线","summary":"比较固定点和右侧邻近点连线的斜率。","coefficients":[0,0,1],"domain":[-0.25,2.7],"baseX":1,"gap":{"min":0.02,"max":1.5,"value":1.2}}
```

### `surface_slice`

允许字段：`version`、`type`、`title`、`summary`、`coefficient`、`radius`、`height`。

- `coefficient` 必填，范围为 `[0.2, 5]`。
- `radius` 必填，范围为 `[0.5, 3]`。
- `height` 必填，格式为 `{"min":数,"max":数,"value":数}`。必须满足 `0 < min ≤ value ≤ max ≤ coefficient·radius²`。
- 允许 `min` 与 `max` 相等。这时参数滑块禁用。
- 曲面为 `z = coefficient·(x² + y²)`。水平截面的圆半径为 `sqrt(height / coefficient)`。

```learn-scene
{"version":1,"type":"surface_slice","title":"曲面水平截面","summary":"改变高度，观察圆形交线半径的变化。","coefficient":1,"radius":1.5,"height":{"min":0.16,"max":2,"value":1.44}}
```

## 旧版生成记录与当前入口

旧版 `learn-scene` 曾用于自动选图、旧正文补图和辅导动画。其 `{needed, reason, scene}` 合同、`diagram` 动画检查和补生成规则只描述旧版行为，不是当前生成合同。保留这些规则是为了说明既有 v1 正文如何读取和显示。

首次生成节点时，前端先请求 `/path/node` 并设置 `defer_visual: true`。服务端校验并保存正文和测验题，再独立请求 `/path/node/scene` 生成动画。这个入口使用 `ManimService`。服务端生成并复核真实视频，再将 `learn-manim` 资产引用写入正文。失败时保留正文和测验题，并把 `manim_review` 记为可重试的 `failed`；不会发布未通过复核的资产，也不会用 v1 场景或 SVG 代替。没有动画价值时自动任务记录 `not_needed`。动画重试不换题，也不改学习进度。资料、节点或正文发生变化时，服务端拒绝旧结果。

刷新页面只恢复读取已有任务回执并继续观察，不重新提交生成请求。页面先显示学习材料，再显示动画状态。批量生成显示一条汇总；用户可展开任务失败列表和原始日志。每个后台执行的预算是 600 秒，自动执行最多两次。自动重试只用于已知传输异常、执行截止和指定上游 HTTP 错误；内容、权限和冲突错误不重试。发布不会批量改写已有用户动画。

AI 辅导的明确动画请求也由 `http_handler` 调用同一个 `ManimService`。服务端只检查本次问题。模型输出的 `learn-scene` 或 `learn-manim` 围栏不会作为资产发布；服务器在辅导正文结束后生成并附加真实动画。正文先正常显示；动画失败时保留讲解并报告失败。

`sceneSupplement` 是旧 v1 补图状态的兼容字段。当前动画状态由服务端维护的 `manim_review` 表示。旧客户端不能伪造或清除这两个受保护字段。现有资料不会被批量改写。

## 渲染、失败与保存

1. 流式输出尚未闭合的围栏时，界面显示占位内容，不解析或挂载半截 JSON。
2. 收到闭合围栏后，renderer 校验版本、类型、字段、数值范围和长度。有效场景按 Markdown 中的顺序渲染；每个内容 root 最多接受四个场景。计数包括有效、错误和隐藏区域里的场景。
3. 无效场景单独显示失败原因和可读的原 JSON。周围正文继续显示。修正后的源内容可以重新渲染。无效围栏仍保留在 Markdown 导出中，供后续修正。
4. 隐藏的答案区域不挂载场景。该区域通过现有显示流程打开后，由 `enhance` 再处理其中的场景。
5. 控件只改变本次页面中的图形状态。它们不改写 Markdown、节点正文、测验数据或学习进度。保存和导出保留原始场景 JSON 与正文，不写入当前滑块值或播放进度。

场景数据只描述 renderer 明确支持的四种图形。用户可见文本按文本内容处理。不得把字段解释为 HTML、脚本、URL、文件路径或模型可执行代码。

## 生成纪律

- 场景只用于概念讲解，不属于考试，也不替代题目合同。
- 题干图示只呈现已知条件，不包含答案或暗示正确选项。辅导场景不得提前泄露正在作答题目的答案。
- 遵守引导式学习纪律。学习者提交作答后再评估；只有学习者明确索要时才给完整解答。
- 场景 JSON 是配置数据。生成 Agent 不输出 HTML、JavaScript、CSS、URL、脚本或可执行表达式，也不声称已经通过浏览器验证。

## 协议扩展

v1 的字段集合是封闭的，未知字段必须拒绝。增加字段约束、图形类型或渲染行为时，先更新规格，再同步修改提示词、renderer 校验与绘制、回归用例和本文档。改变已有字段的含义或范围时提升协议版本；新类型使用新的 `type` 名称。不得让 Agent 在 v1 对象里自行发明扩展字段。

本文描述协议和实现约束，不代表功能已经部署或完成浏览器验收。
