# Quiz Harness v2：结构化作答与计分

新签发题目使用 v2；计分规则在出题时确定，独立验题通过后随轮次保存。提交请求只携带作答，不能改变题型、分值、答案或计分模式。既有轮次与历史成绩不追溯改写。

## 题型和分值

| type | scoring.mode | 分值来源 | 计分方式 | 作答格式 |
|---|---|---|---|---|
| choice | single_choice | 题目 points | 正确选项得题目分值，否则 0 | `"A"` 等单选字母 |
| fill | per_blank | 每空 points，合计等于题目 points | 逐空匹配，正确空得分相加 | `["第一空", "第二空"]` |
| fill | all_or_nothing | 仅题目 points | 全部空匹配才得题目分值，否则 0 | `["第一空", "第二空"]` |
| short | rubric | rubric 每项 points，合计等于题目 points | 模型判断已固定评分点，程序相加 | 作答文本 |

- 每题 points 必须是 1~100 的整数，全卷总分必须为 100；通过分数为 60。
- 单元测验固定 4 道选择、1 道填空、1 道简答；综合测验 1~16 题。
- 填空模式默认要求出题模型选择 per_blank；只有各空必须整体正确的题目使用 all_or_nothing。
- 每题 `scoring` 只允许 `mode`，非法或遗漏模式不能签发。填空必须有 1~16 个有序 blanks，题干用 `____` 标记对应空位。
- 数学填空也用原始 `____` 标记空位。先结束 `$...$`、`$$...$$`、`\(...\)` 或 `\[...\]` 公式，再写 `____`。例如：`$\det\mathbf{A}=$ ____`。多分量结果应要求分别填写各分量。不要用 `\square`、`\_`、HTML 或其他符号替换 `____`。
- 每空 id 必须依次为 b1、b2……；必须有 answer 和 1~32 个 accepted_answers，且包含参考答案。禁止未知空位规则字段。
- per_blank：每空 points 为正整数、总和必须等于本题 points。all_or_nothing：空位禁止声明 points，避免把“未单独计分”误表示成“每空 0 分”。
- 单选和旧题沿用原标准化匹配；v2 填空忽略 Unicode 全半角和空白，**区分大小写**，每空声明 `match: text`（文本匹配）或 `match: numeric`（允许有限小数/分数数值等价）。考查未约分、最简等形式时使用 text。`float64(X)` 不等于 `float64(x)`。同义词必须提前列入该空 accepted_answers，不在批改时让模型临时改规则。

## 定制例子：两空 8 + 12 分

```json
{
  "type": "fill",
  "q": "int 变量 x 转换为 float64 写作 ____；Go 不允许 ____ 类型转换。",
  "points": 20,
  "scoring": {"mode": "per_blank"},
  "blanks": [
    {"id": "b1", "answer": "float64(x)", "accepted_answers": ["float64(x)"], "match": "text", "points": 8},
    {"id": "b2", "answer": "隐式", "accepted_answers": ["隐式", "隐式的"], "match": "text", "points": 12}
  ],
  "answer": "float64(x)；隐式",
  "explain": "Go 使用目标类型显式转换，不会自动转换这两个数值变量的类型。"
}
```

若要整题计分，将 mode 改为 `all_or_nothing`，并删除两个空的 points。题目 points 仍为 20，两个空全部正确才得 20 分。不能修改已签发轮次来重新解释历史成绩；新规则签发为新轮次。

`answer` 是兼容旧展示和学习反馈的可读摘要，程序从 blanks 中的参考答案生成；它不是用分号传输作答的协议。结构化参考答案数组始终可直接得满分，即使某个答案本身含分号、逗号或换行。

选择题声明 `"scoring":{"mode":"single_choice"}`；简答题声明 `"scoring":{"mode":"rubric"}` 并保留原 rubric 结构。自定义题目须经过 `validate_questions` 的代码校验和 `_checked_questions` 的独立验题；不是客户端写入状态即可成为可信题目。

## 作答、草稿与结果

请求顶层 answers 按题目次序排列；选择和简答是字符串，填空是逐空字符串数组。漏答必须保留空字符串位置，例如 `answers[4] = ["", "隐式"]`，不能删掉第一空。每题作答总长度最多 20000 字符；服务器拒绝错误空位数量、嵌套对象、非文本值和超长作答。

per_blank 的逐题结果提供 `mode`、`earned`、`max_points` 和 `blanks`。每空结果包括 id、ok、answer、comment、earned、max_points。all_or_nothing 每空仅提供正确性与理由，没有 earned/max_points；题目级别返回实际得分。全卷总分只由程序相加产生。

每次输入保存原始数组；切换题集、关闭和重新进入可恢复草稿，历史提交只读。相同轮次相同请求按 attempt_id 幂等，客户端提供的题目/分值/模式不参与判分。

## 界面

题干下始终显示模式和分值，不需要先查看答案：

- 选择题：整题计分、正确/错误分值。
- 按空填空：每个空独立输入框、编号、分值；逐空得分和整题得分分开显示。
- 整题填空：标明全部空正确才得分、各空不单独计分。
- 简答：按评分点计分及总分。参考答案、解题思路、详细 rubric 保持确认后展开。

## 兼容边界

旧题没有 blanks/scoring 时继续使用旧整题答案匹配，界面明确标为“旧题整题计分，未设置每空分值”。按题干下划线或空括号识别输入空位，不反推或平分分值。旧字符串先尝试按分号、换行、逗号拆成恰好对应的空数；无法无歧义拆分的内容完整保留在第一空，供用户调整，不丢弃文本。

已保存的旧成绩不重算。新格式提交到旧题时由后端兼容组合整题文本并沿用预设匹配规则；这不等同于对旧题补上逐空同义词契约。要获得严格逐空计分，应重新出题。

## 验证入口

`scripts/check-local.sh` 包含结构化契约与实际 HTTP 草稿/评分/回读回归。测试材料只能写入隔离状态目录，不得进入正式学习库。发布后还需通过两处测验的真实浏览器和模型出题回归。

新签发每空必须明确 match。此前已签发 v2 题未提供 match 时保留原 numeric 规则，不追溯改写历史。修改匹配要求需签发新题。
